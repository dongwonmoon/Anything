## 06.26
- 리팩토링 계획 문서 작성: 배포까지 진행했으므로 추후 개발 편의를 위한 리팩토링 준비
	- Core User Promises 정의
		- 1. 기록 보존: 저장한 기록은 앱을 껐다 켜도 유지되어야 함
		- 2. 빠른 기록 작성: 사용자는 사진이나 책 없이도 문장 또는 메모만으로 기록을 저장할 수 있어야 한다. 사진, 책, 페이지는 선택 사항이다.
		- 3. 사진 lifecycle: 첨부한 사진은 기록과 함께 보이고, 수정/삭제 시 기록 상태와 어긋나면 안된다.
		  삭제한 기록의 사진이 앱 안에서 계속 보이면 안된다.
		- 4. 책 검색 독립성: 책 검색은 기록을 풍부하게 하는 선택 기능이다. 책 검색 실패가 기록 작성 자체를 막으면 안된다.
		- 5. 뒤로가기 예측 가능성: 화면 안 "<" 버튼과 Android 뒤로가기는 사용자가 기대하는 journey와 크게 어긋나면 안된다. 또한 같은 journey를 공유해야한다.
		- 6. 삭제의 명확성: 기록 삭제는 확인 후에만 수행되어야 하고, 삭제 후 목록/홈/상세가 삭제된 기록을 다시 보여주면 안된다.
		- 7. 주요 화면의 기본 사용성: 홈, 작성, 상세, 기록 탭은 일반적인 Android 화면 크기에서 핵심 CTA가 접근 가능해야한다. 키보드가 메모 입력이나 저장 버튼을 실질적으로 막으면 안된다.
	- Refactor Risk Areas 정의: 이 사용자 약속들을 깨뜨릴 가능성이 높은 코드/UX 영역은 어디인가?

	- Navigation / route params 조사
	- Navigation regression journeys 정의
		- 기록 탭 -> 상세 -> "<" 버튼 혹은 Android Back -> 기록 탭
		- 홈 최근 기록/다시 펼쳐보기 -> 상세 -> "<" 버튼 혹은 Android Back -> 홈
		- 기록 탭 -> 상세 -> 수정 -> 저장 -> 상세 -> "<" 버튼 혹은 Android Back -> 기록 탭
		- 상세 -> 수정 -> 책 선택 -> 책 선택 -> 수정 화면 -> "<" 버튼 혹은 Android Back -> 상세 -> "<" 버튼 혹은 Android Back -> 원래 root
		- 상세 -> 책 연결하기 -> 책 선택 -> 상세 -> "<" 버튼 혹은 Android Back -> 원래 root
		- 기록 탭 -> 상세 -> 삭제 -> 기록 탭
	- Local record lifecycle
		- 저장된 기록의 원본: SQLite
		- create draft와 saved record는 다름
		- create draft와 edit draft는 다름
		- 직접 책 연결과 수정 중 책 선택은 다르다
			- 직접 책 연결: 바로 saved record를 변경 및 mutation
			- 수정 중 책 선택: edit draft만 변경
		- 삭제와 cleanup은 분리되어 있다
			- 삭제는 saved record row를 hard delete. 그 다음 사진 파일 cleanup은 best effort
