## 한 줄 정의

> **사용자가 목표를 달성하는 과정에서 실제로 불편, 혼란, 지연, 위험, 부담을 느끼는 지점**

---

## 왜 중요할까?

예를 들어, Journey가
Journey:
> 1. 서비스에 접근한다.  
> 2. 회원가입 버튼을 누른다.  
> 3. 이메일을 입력한다.  
> 4. 비밀번호를 입력한다.  
> 5. 개인정보를 입력한다.  
> 6. 약관에 동의한다.  
> 7. 이메일 인증을 한다.  
> 8. 가입 완료 후 원래 하던 작업으로 돌아간다.

그렇다면, Pain Point는
Pain Point:
> 회원가입 버튼이 안보인다.
> 비밀번호 조건을 제출 후에야 알려준다.
> 개인정보를 왜 입력해야 하는지 모르겠다.
> 약관 필수/선택 구분이 어렵다.
> 인증 메일이 안 온다.
> 가입 후 원래 하던 페이지로 돌아가지 못한다.

Journey가 길이라면, Pain Point는 방지턱!

---

## Pain Point의 종류

| 종류       | 의미           | 예시                  |
| -------- | ------------ | ------------------- |
| 인지적 Pain | 이해하기 어렵다     | 버튼 이름이 애매함          |
| 시간적 Pain | 오래 걸린다       | 인증 메일 지연            |
| 절차적 Pain | 단계가 많다       | 가입 중 입력할 것이 너무 많음   |
| 감정적 Pain | 불안하거나 짜증난다   | 결제 완료 여부가 불명확함      |
| 기술적 Pain | 오류나 버그가 있다   | 파일 업로드 실패           |
| 정보 Pain  | 필요한 정보가 없다   | 배송비가 마지막 단계에 나옴     |
| 신뢰 Pain  | 믿기 어렵다       | 개인정보를 왜 요구하는지 설명 없음 |
| 회복 Pain  | 실패 후 복구가 어렵다 | 오류 후 입력값이 전부 사라짐    |
| 비용 Pain  | 돈이나 리소스가 든다  | 다운로드할 때마다 과금 발생     |
| 운영 Pain  | 내부 담당자가 힘들다  | 운영자가 매번 DB를 직접 수정함  |
(이거 외에도 많음)
Pain Point는 사용자 뿐만 아니라, 운영자, 개발자, 고객지원 담당자 등 모두에게 적용될 수 있음.

---

## Pain Point를 찾는 방법

> 1. User Journey를 단계별로 적는다.
> 2. 각 단계에서 사용자의 기대를 적는다.
> 3. 실제 시스템의 반응을 적는다.
> 4. 기대와 실제의 차이를 찾는다.
> 5. 그 차이가 불편, 지연, 혼란, 불안, 실패로 이어지는지 본다.

예를 들자면,

| 단계      | 사용자의 기대         | 실제 경험      | Pain Point   |
| ------- | --------------- | ---------- | ------------ |
| 비밀번호 입력 | 조건을 미리 알고 싶다    | 제출 후 오류 표시 | 재입력 짜증       |
| 이메일 인증  | 바로 메일이 오길 기대    | 메일 지연      | 가입 중단        |
| 결제 완료   | 결제 성공 여부를 알고 싶다 | 화면이 멈춤     | 중복 결제 불안     |
| 파일 업로드  | 업로드 성공을 알고 싶다   | 진행률 없음     | 실패한 줄 알고 재시도 |

```
회원가입의 비밀번호 입력 단계를 Pain Point 관점에서 분석해줘.

다음 항목으로 나눠줘.

1. 사용자의 기대
2. 실제로 겪을 수 있는 불편
3. 인지적 Pain Point
4. 절차적 Pain Point
5. 기술적 Pain Point
6. 보안 요구사항과 사용성의 충돌
7. 사용자가 이탈할 수 있는 지점
8. 개선 방향
9. MVP에서 반드시 반영해야 할 것
```
